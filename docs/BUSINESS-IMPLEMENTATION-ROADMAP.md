## Locked rules

Meeting may use uu_pay or external when negotiated before acceptance; Seller delivery/Courier remain uu_pay only. Payment mode freezes into Order terms, legacy resolves uu_pay; no retroactive mode switch. Buyer Protection fee applies only to uu_pay; preserve versioned historical economics. Both participants must confirm frozen Agreement before Payment eligibility for applicable unpaid Orders; paid/history progress is not regressed.

External Meeting: no Stripe, Payment stage, QR/code handoff,24h financial protection, UU seller payout/refund/settlement. Both immutable exchange attestations are required for Completed/Sold; after one attestation ordinary cancellation/auto-expiry/inventory release is blocked. Disagreement is non-financial and cannot be presented as protected payment adjudication. Preserve existing implementation/tests rather than redesigning it in the payment project.

uu_pay continues its existing Agreement -> Payment -> fulfillment/inspect -> Handoff -> Protection -> Completed path where applicable; courier uses its own fulfillment labels/gates. Provider payment status must never be inferred solely from browser redirect or setup readiness.

## Provider and browser boundary

Use existing server-only provider setup adapter and environment guards. Read current provider documentation during the separately authorized implementation; this roadmap is not a substitute for current API verification. Do not change Accounts v2/hosted onboarding merely to implement billing. Order charging and Shop subscription are separate capabilities with explicit identifiers and audit trails.

Required qualities: stable operation UUID and provider idempotency key; verified raw-body webhook signature and endpoint scope; durable unique provider event ID; reject wrong test/live/account/object linkage; replay-safe inbox; crash-safe retry; authoritative reconciliation; sanitized logs; amount/currency/destination from frozen server records. A provider webhook alone must still pass existing Order authorization guards. Browser may initiate an authorized command and render results, never assert paid/refunded/eligible/entitled or supply service-role credentials.
